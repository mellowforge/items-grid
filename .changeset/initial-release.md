First release: card grids that fit the screen exactly. Size presets (compact, normal, large or custom) with `maxColumns` and `maxPageSize`, fixed or measured row height, client or server paging, live or stable realtime reflow with a pending-items count, per-slot skeletons, an empty state, top or centred alignment and an optional pager — as a headless core with a vanilla mount, a React component and an Angular component. Apps get an `ItemsGridHandle` for navigation, unknown server totals are supported (`totalKnown`), PageUp/PageDown page the grid with screen-reader announcements, and invalid options throw `items-grid:` errors without changing anything. When app code (`getKey`, `messages`) throws while the grid works out a new page, `setOptions`, `goTo` and `refresh()` change nothing, and viewport and row-height reports keep the page (but not a stale size); a request whose `onPageRequest` threw does not count as sent, so the next update asks again once. The React adapter renders on the server without layout-effect warnings. An opt-in `arrowKeys` (vanilla option, React prop, Angular input) moves focus between cards with the arrow keys, Home and End — one card is the tab stop, the arrows cross pages, card controls keep their own keys, and when the focused card leaves the page (paging, a resize, a realtime removal) focus moves to the card at the same position; `attachCardNavigation` and `getCardMove` expose it for custom renderers. Both adapters take a custom pager: React's `pager` render function and Angular's `ng-template[mfItemsGridPagerTemplate]`, rendered below the cards with the grid's `state` and `controller`. The optional pager stylesheet (`@mellowforge/items-grid-core/styles.css`) adapts to dark pages: its colours derive from the text colour, and its default accent follows `color-scheme: dark` (or `light dark` on a dark OS) through `light-dark()`; browsers without `light-dark()` keep the light accent, and the `--mf-items-grid-pager-current-*` and `--mf-items-grid-focus-ring` overrides still win.
